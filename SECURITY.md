# Security Policy

## Supported Versions

Security reports are accepted for the following project versions:

| Version | Supported |
| --- | --- |
| Current `main` branch | Yes |
| Latest published release | Yes |
| Older releases | No |

Security fixes, when required and practical, will target the current `main`
branch. A corresponding release may be published when appropriate.

## Reporting a Vulnerability

Please do not disclose suspected vulnerabilities in a public GitHub issue,
discussion, pull request, or other public channel.

Use the repository's **Report a vulnerability** option under
**Security → Advisories** to submit a private report through GitHub Private
Vulnerability Reporting.

Include, where applicable:

- a concise description of the issue;
- the affected release, commit, or live deployment;
- reproducible steps or a minimal proof of concept;
- the expected security impact;
- relevant environment or configuration details;
- any known mitigation or suggested remediation.

Please avoid including unrelated personal, confidential, or sensitive data.

## What to Expect

Reports will be reviewed as maintainership capacity allows. No fixed
acknowledgement, response, or remediation timeline is guaranteed.

The maintainer may request additional information to reproduce and assess the
reported issue. Valid findings may be handled privately through a GitHub
Security Advisory while a fix or mitigation is prepared.

Please allow reasonable time for investigation and coordinated remediation
before public disclosure.

## Non-Security Reports

General defects, usability problems, documentation issues, and feature requests
that do not expose sensitive information may be reported through the public
issue tracker.
